# 日常运行、失败恢复与回滚

## 日常查看

每天收取早晚邮件，先检查是否为 AI 增强版、是否有来源异常，再阅读来源和两种草稿。复制附件或草稿区正文后手动发布 X。系统不记录你的 X 登录态，也不自动确认你是否已经发帖。

首页显示最近期号、截止和生成时间；历史页保留每期最新修订，`revisions` 保留旧修订。日报与 X 草稿共用同一冻结数据，补发不会改变内容。

## 手动工作流

| 模式 | 效果 |
|---|---|
| `preview` | 只生成演示网页，无业务 Secrets、AI 调用、发信或部署 |
| `check-sources` | 只读检查真实信源，20/8 门槛未达则失败 |
| `run` | 生成指定已结束期号；已存在则复用，重试部署和未完成邮件 |
| `regenerate` | 重新采集、可能调用 AI、生成新修订；旧修订保留 |
| `redeploy` | 从已冻结日报重建并部署网页，不调用 AI、不发信 |
| `send` | 从已冻结日报生成草稿并发信，不采集、不部署 |
| `check-ai` | 使用已冻结的公开证据检查真实AI，计入该期额度，不部署、不发信，只报告固定错误码 |
| `enhance-issue` | 将已有规则日报补做AI并生成新修订、部署和邮件；不重新采集、不改截止时间，计入同一期额度 |
| `test-enhance` | 仅仓库Owner人工授权的独立联调，最多额外5次（需明确授权），单独持久化计数，仍计入当前模型免费日配额；不会自动用于生产 |

独立联调要求仓库Variable `AI_TEST_AUTHORIZED_ISSUE` 精确指定期号、`AI_TEST_AUTHORIZED_TOTAL` 指定经用户明确批准的累计测试上限（最多5，仍受当前模型免费日配额保护）。例如之前已测2次、再批准1次时累计上限设3，旧计数2保留，仅能再调用1次。工作流只在Owner手动触发该模式时传递授权。联调后删除这两个Variable；生产每期20次计数不重置。固定错误码记录在公开状态的 `ai_audit`，不包含Key、完整服务商响应或模型正文。

`resend=true` 只在确认需要重复发送后使用；可能给已收到邮件的收件箱再发一封。

## 邮件状态

`pending/disabled → sending → sent`。明确未接受的连接、认证或收件人失败记录为 `failed`，总计最多 3 次自动尝试；DATA 之后结果不明确记录为 `unknown`。进程遗留的 `sending` 也按结果未知处理。

遇到 `unknown` 先检查收件箱和垃圾邮件。不要直接反复点“重新运行”。需要时显式补发。Message-ID 固定有利于邮箱整理，但不能保证收件方自动去重。

若服务商已接受而远程状态保存失败，远程仍保留发送中标记，下一次不会自动重发。邮件内容不作为日志输出。诊断提供状态码和异常类型，不输出服务商响应文本。

## 常见故障

- **来源错误**：查看来源健康结果的 `error_code`；修复配置或网络后重跑来源检查。单源失败不阻断其他来源，全源失败不推进覆盖时间。
- **规则降级**：核验开关、免费账单确认、Key 和实际配额。不要通过提高配置值超过账户真实限额。确认修复后，对新期号运行或显式生成新修订。
- **网页未生效**：运行 `redeploy`。只有实际页面包含本期修订标记才记录 `ready`；200 状态码本身不够。
- **邮件失败**：检查 Secrets、SMTP 开关、授权码和服务商限制。仅 `send` 补发，不需要再次调用模型。
- **错误新闻**：调整来源/规则后使用 `regenerate` 生成修订，保留此前版本；已手动发到 X 的帖子由你自行更正。
- **定稿事实更正**：在 `config/corrections/<期号>.json` 指定冻结 `base_key` 和按条目 ID 的文字更正，使用 `review-issue`。只允许修改标题、摘要、影响、不确定性与选稿理由；重新读取原始证据、检查数字数量级和币种，再调用一次 AI 终审（格式修复和瞬时重试仍计入本期 20 次）。通过后保存新修订，不部署、不发信；人工复核后依次 `redeploy`、`send`。原版本和请求计数均保留。
- **任务完全没有启动**：同一套工作流无法可靠检测自己的停用。定期查看 Actions 和首页更新时间，检查 GitHub 定时工作流的 60 天无活动条件和通知设置。

### 错误码

来源诊断：`timeout`、`connection_failed`、`http_403/429/...`、`unsafe_target`、`parse_failed`、`source_unavailable`。诊断文件仅含信源 ID、可信等级、状态和计数。

CLI 默认只打印安全状态和异常类型。需要调试时在本地固定样例中复现，禁止把完整请求响应、邮件或 Secrets 输出到公共 Actions 日志。

## 暂停与恢复

- 总暂停：`PUBLISHER_PAUSED=true` 或停用 News Publisher 工作流。
- 停止 AI：`AI_ENABLED=false`，系统转规则版。
- 停止邮件：`EMAIL_ENABLED=false`，日报仍可生成和部署。
- 恢复总运行：核验配置和失败原因后取消暂停，先手动运行一个期号。

## 回滚

恢复此前经过验证的代码提交；不要强推删除公开日报历史。仅重新部署页面时使用冻结 JSON 构建，避免重新消耗 AI 额度。

若需要恢复历史数据状态，先保存当前 `news-data` 快照，在本地比较目标状态及邮件发送标记，再通过正常提交恢复。**不要把已经发送的邮件状态回滚为 pending**，否则可能重复推送。AI 调用计数也不应因回滚清空。

数据模式目前为 `schema_version=1`。以后改变结构必须提供明确迁移，不能直接忽略未知字段。无效状态应停止处理，不静默重置历史。
